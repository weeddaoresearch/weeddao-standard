# WeedDAO v0.2-draft Design

**Status:** evidence-driven draft (not a release)  
**Schema:** `schemas/weeddao-record-v0.2-draft.schema.json`  
**Title:** WeedDAO Cannabis Data Record v0.2 Draft  
**`schema_version` const:** `0.2-draft`

## Why v0.2-draft

Corpus v0.1 (50 public COAs) showed four **critical interoperability** gaps against frozen v0.1-alpha:

| Issue | Gap | Relevant cases |
|------:|-----|---------------:|
| #1 | Below-reporting-limit qualifier (`<LOQ` / `<LOD`) | 35 |
| #2 | Analyte-level NOT_TESTED / NOT_PERFORMED | 22 |
| #3 | ND / not detected for quantitative analytes | 48 |
| #4 | Concurrent multi-unit cannabinoid values | 43 |

v0.1 also forced finished-product COAs into `cultivation_batch_id` and product trade names into `cultivar`. v0.2-draft fixes subject semantics and analyte result states in **core**, without inventing speculative features beyond corpus evidence.

Pipeline limitations (unparsed tables, missing batch placeholders) are **not** schema requirements.

## Subject model (required)

`subject` is required:

- `subject_type`: `cultivation_batch` | `harvest_lot` | `product_batch` | `sample` | `other`
- `subject_id` (required)
- optional: `name`, `product_type`, `matrix`, `external_identifiers`

`cultivation_batch_id` is **optional** (migration aid only; primarily when `subject_type=cultivation_batch`).

**Cultivar = genetics only.** Finished-product trade names belong in `subject.name`, never in `cultivar`.

## ExternalIdentifier

`scheme`, `value`, optional `jurisdiction`, `scope`. Open schemes (examples: `metrc.package`, `metrc.source`, `lab.sample`, `producer.lot`).

## AnalyteResult

Core result object used for cannabinoids, terpenes, and safety analytes:

- `result_state`: `detected` | `not_detected` | `below_reporting_limit` | `not_tested` | `not_performed` | `not_reported` | `not_applicable` | `withheld` | `unknown`
- `measurements[]` (multi-unit)
- `limits[]` (`LOD` | `LOQ` | `reporting_limit` | `action_limit` | `regulatory_limit` | `other`)
- `assessment`: `pass` | `fail` | `not_applicable`
- optional: `reported_as`, `method`, `provenance`, `notes`

**Never coerce** ND → 0, `<LOQ` → 0, NOT_PERFORMED → missing, NOT_TESTED → pass.

### Conditional validation (Draft 2020-12 `if`/`then`)

- `detected` → ≥1 numeric `measurements` entry
- `below_reporting_limit` → ≥1 `limits` entry **or** `reported_as`
- non-detected states → measurements not required

### Units

Extensible string units. Documented examples include `%`, `mg/g`, `mg/ml`, `mg/serving`, `mg/unit`, `mg/package`, `ppm`, `ppb`, `µg/g`, `ng/g`, `CFU/g`. Optional `basis` / `basis_quantity` on measurements.

## Cannabinoids / terpenes / safety

- **Cannabinoids:** familiar keys as `AnalyteResult` plus `other[]` of named results.
- **Terpenes:** named array; ND representable in core.
- **Safety:** panel `status` separate from per-analyte `AnalyteResult`. Panel statuses include `pass` | `fail` | `partial` | `not_tested` | `not_performed` | `not_reported` | `not_applicable`.
- **`not_reported`** is first-class at analyte and panel level.
- Optional under `lab_results.sample`: sample lifecycle metadata (`SampleLifecycle`).
  - Fields: `sample_id`, `collected_at`, `received_at`, `reported_at`, `produced_at`, `harvested_at`, `matrix`, `collection_party`, optional free-text `collector`, `notes`.
  - `reported_at` captures the report/certification datetime when the source provides it.
  - `collection_party` is categorical: `client` | `laboratory` | `third_party` | `unknown`. Omit when the source does not establish the collection party; use `unknown` only when a collection event is established but party identity cannot be classified. Must not require personal names.
  - Optional `collector` remains a non-required free-text / source label for draft compatibility and must not require personal names; prefer `collection_party` for categorical semantics.
  - `collected_at`, `received_at`, `lab_results.tested_at`, and `reported_at` are distinct lifecycle events and must never be silently substituted for one another.

- Optional metadata (not mandatory): `foreign_material`, `moisture`, `water_activity`, `best_by`, `homogeneity`.

## COA-046 FAIL semantics

Potency-spec FAIL, homogeneity FAIL, and contaminant safety FAIL are **distinct**:

- potency-spec → cannabinoid `assessment: fail` + outcomes `failure_types`
- homogeneity → `lab_results.homogeneity`
- do **not** map potency FAIL as contaminant panel FAIL

## Explicit non-goals

- No v0.2 release or tag in this draft
- No rewrite of `corpus/v0.1`
- No refetch of COAs from the web
- No change to frozen v0.1-alpha schema or `v0.1-alpha` tag
