# Outreach copy — request independent review (v0.2-draft)

Tone: invite technical/domain review. Not sales. No adoption claims. No tokens, blockchain, or product pitch.

**Core framing:** We are seeking independent expert review of WeedDAO Cannabis Data Record `v0.2-draft` — an evidence-driven proposed JSON language for cultivation, harvest, product-batch, and lab summaries so different platforms and organizations can exchange data more consistently. `v0.1-alpha` remains the published frozen baseline; `v0.2-draft` is not a release.

**Tagline:** Different platforms. Different organizations. One shared data language.

**Branch:** https://github.com/weeddaoresearch/weeddao-standard/tree/v0.2-draft

## Grower / cultivation operator

Subject: Review request — WeedDAO cannabis data record v0.2-draft (subject model)

Hi —

We drafted an experimental JSON record shape for cultivation and harvest lots, driven by gaps found across a 50-COA public corpus. It is a proposed shared data language, not a certification program and not regulatory.

If you have 10–15 minutes, we would value a grower’s eye on whether `subject` typing and optional grow/harvest sections match real batch records. Brief: `docs/v0.2-external-review-brief.md`. ## Laboratory / LIMS

Subject: Review request — AnalyteResult semantics in WeedDAO v0.2-draft

Hi —

WeedDAO `v0.2-draft` proposes separating `result_state` (detected / ND / below-limit / not performed / not reported) from pass/fail `assessment`, with multi-unit `measurements[]` for COA exchange (not a lab method standard).

We are asking labs and LIMS practitioners whether those shapes are usable when mapping real COAs. Start with `docs/v0.2-external-review-brief.md` (questions 3–7, 10). Branch: https://github.com/weeddaoresearch/weeddao-standard/tree/v0.2-draft Identity optional.

Thank you for considering an expert review.

## Researcher

Subject: Review request — provenance, ND, and lifecycle semantics (WeedDAO v0.2-draft)

Hi —

WeedDAO `v0.2-draft` is a proposed open cannabis data record (working draft) with explicit analyte result states, genetics-only cultivar fields, and distinct sample lifecycle timestamps when sources provide them.

We would appreciate research feedback on whether those semantics support reproducible exchange without sentinel zeros. Brief: `docs/v0.2-external-review-brief.md`. Branch: https://github.com/weeddaoresearch/weeddao-standard/tree/v0.2-draft Not a claim of adoption; experimental only.

## Dispensary / product-data operator

Subject: Review request — product-batch subject model (WeedDAO v0.2-draft)

Hi —

Many finished-product COAs do not fit a cultivation-batch-only record. WeedDAO `v0.2-draft` introduces `subject_type: product_batch`, genetics-only `cultivar`, and external identifier slots for track-and-trace IDs.

If you work with retail/product master data or dispensary inventory systems, we would value feedback on whether that subject model and multi-unit potency fields are usable for exchange. Brief: `docs/v0.2-external-review-brief.md`. Branch: https://github.com/weeddaoresearch/weeddao-standard/tree/v0.2-draft Identity optional; no adoption claims.
