# Migrating WeedDAO records: v0.1-alpha → v0.2-draft

## Breaking changes

1. **Required `subject`** replaces required `cultivation_batch_id`.
2. **`schema_version`** becomes `0.2-draft` (v0.1 uses `0.1-alpha`).
3. **Cannabinoid / terpene / safety analyte shapes** move from `{value, unit}` to `AnalyteResult` (`result_state`, `measurements[]`, `limits[]`, …).
4. **`cultivar`** is genetics-only. Product names must move to `subject.name`.
5. Panel status vocabulary expands (`not_performed`, `not_reported`, …).

## Field mapping cheat sheet

| v0.1-alpha | v0.2-draft |
|------------|------------|
| `cultivation_batch_id` (required) | `subject.subject_id` + `subject.subject_type`; optionally keep `cultivation_batch_id` when type is `cultivation_batch` |
| `cultivar.reported_name` used as product title | `subject.name` for products; cultivar only if genetics known |
| cannabinoid `{value, unit}` | `{result_state: "detected", measurements: [{value, unit}]}` |
| omitted ND / `<LOQ` (gap / extension) | `result_state: "not_detected"` or `"below_reporting_limit"` in core |
| single unit only | `measurements[]` with concurrent units |
| safety analyte ND encoded awkwardly | `AnalyteResult.result_state: "not_detected"` |
| extension bags for issues #1–#4 | **core** AnalyteResult / subject / external_identifiers |

## Subject typing guidance

| Source reality | `subject_type` |
|----------------|----------------|
| Grow / cultivation lot | `cultivation_batch` |
| Harvest / biomass lot | `harvest_lot` |
| Finished retail/manufactured batch (edible, vape, concentrate, pre-roll, …) | `product_batch` |
| Lab sample identity primary | `sample` |
| Unclear | `other` |

## Semantically forbidden migrations

- Do not keep finished-product IDs solely as `cultivation_batch_id` without a correct `subject`.
- Do not leave product trade names in `cultivar`.
- Do not encode ND / `<LOQ` / NOT_PERFORMED as `0`, `null`, or omitted-without-state.
- Do not collapse potency-spec or homogeneity FAIL into contaminant safety `fail`.

## Compatibility

v0.1-alpha remains frozen. Validators:

- `scripts/validate.py` — v0.1-alpha
- `scripts/validate_v0.2.py` — v0.2-draft (+ `--shadow` for corpus mappings)

Shadow mappings under `corpus/v0.2-draft/` are derived **only** from `corpus/v0.1` facts (no COA refetch).
